Supabase Auth settings checklist

DNS is only half of it. A public page can't see these settings (they live inside your Supabase dashboard), so tick them off yourself. Paths are from the Supabase dashboard.

  • Site URL is your real live address, not http://localhost:3000 or a preview host. Authentication → URL Configuration → Site URL. Supabase uses it as the default link in confirmation and reset emails, so if it's wrong, every email link points to the wrong place.
  • Redirect URLs list includes every place you send people back to, e.g. https://myapp.com/**. ** matches any path; a single * stops at / and ., so https://myapp.com/* won't match /auth/callback/x. Supabase recommends exact paths for production, with wildcards for local dev and previews.
  • Preview vs. production hosts are both covered, on purpose. If you build on Lovable, Bolt, Vercel or Netlify, the preview host (e.g. *.lovable.app, *.vercel.app) and your custom domain are different. "Works in preview, broken live" usually means only one of them is listed.
  • Custom SMTP is turned on. Authentication → Emails → SMTP Settings. The built-in sender only delivers to your own team's addresses and is limited to 2 emails an hour. Real users won't get anything until custom SMTP is set up (Resend, Brevo, Postmark, ZeptoMail, SES, etc.).
  • Email rate limit raised after SMTP is on. Authentication → Rate Limits. After you add custom SMTP, Supabase starts you at 30 emails an hour. Raise it to fit your signups, and stay under your email provider's own daily cap.
  • Email templates use the right link variable. If your code passes redirectTo, the template link may need {{ .RedirectTo }} instead of {{ .SiteURL }}. A template hard-coded to an old preview URL breaks every email.
  • Sending domain is verified at your email provider (all its DNS records show green). Turn off link tracking for auth emails: tracked links get rewritten and can break or look suspicious.
  • Google sign-in: in Google Cloud → your OAuth client → Authorized redirect URIs contains your Supabase callback, https://<your-ref>.supabase.co/auth/v1/callback (or your Supabase custom domain). Your app's address goes under Authorized JavaScript origins, not in redirect URIs.
  • Test with a real outside inbox (a Gmail address not on your Supabase team): sign up, confirm, reset password, magic link. Check spam too.

Sources: Supabase docs on custom SMTP, rate limits, redirect URLs, Google sign-in.
